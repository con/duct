## Summary

**What is well built**

- **A clean, acyclic import graph with a deliberate public surface.** `ruff analyze graph` shows no cycles. Entry points (`cli.py`) call into the core, the core never imports them, and internals are `_`-prefixed while `con_duct/__init__.py:3-6` exports exactly `execute` and `__version__`.
- **Closed sets are already enums used end to end.** `Outputs`, `RecordTypes` and `SessionMode` (`_models.py:20-56`) feed argparse `choices=list(...)`/`type=` directly (`cli.py:329-366`), so there is no parallel list of strings to drift.
- **The schema has a tripwire.** `test/test_schema.py:9-32` runs duct and asserts that the keys of a real `info.json` equal `LS_FIELD_CHOICES`, so a schema change cannot be forgotten in `ls`.
- **Signal handling is careful and explained.** `_signals.py:16-46` blocks SIGINT around every thread start, and `_signals.py:114-138` documents and handles the re-entrant logging case.
- **Byte units have one definition.** `FILESIZE_UNITS` (`_formatter.py:15-25`) is shared by the run summary and the plot axis.
- **Tooling is enforced, not aspirational.** flake8 (with bugbear, builtins, unused-arguments), mypy over `src` and `test`, and a 0%-threshold jscpd hook all pass at this commit; the baseline suite is 501 tests at 94% branch coverage, plus `minimal` and `oldestdeps` environments.

**Dominant themes**

1. **Environment configuration is read at three different moments.** One variable is read at import (`_duct_main.py:19`), the rest when the parsers are built (`cli.py:213-355`), and `.env` files are loaded in between. That ordering is the root of NV-1 (a documented `.env` setting is silently ignored), NV-3, NV-4 and NV-5, and of ARC-1.
2. **The same facts about `info.json` are written out several times** — the system fields in five places, the field-to-format mapping in two (ARC-2), the package version in two (ARC-3).
3. **A few functions carry most of the complexity.** `matplotlib_plot` (274 lines, cyclomatic complexity 34) and `execute` (172 lines, 21, 14 parameters) are far above the rest of the codebase (ARC-4); the stream setup inside them is duplicated (DUP-2).
4. **Leftovers from the module split**: attributes written and never read, a no-op `except`, inert parser and tox settings (DC-1 to DC-4), and old `typing` spellings in the four modules without `from __future__ import annotations` (CL-1).

### Architecture

#### ARC-1 — `ls` imports the whole run machinery to get one constant

- **Location**: `src/con_duct/ls.py:10`, `src/con_duct/_duct_main.py:19-34`, `src/con_duct/cli.py:10`, `test/utils.py:26`
- **Issue**: `DUCT_OUTPUT_PREFIX` and `EXECUTION_SUMMARY_FORMAT` are configuration defaults, but they live in `_duct_main.py`, next to `execute()`. `ls.py` needs only the prefix (`ls.py:356`), yet `from con_duct._duct_main import DUCT_OUTPUT_PREFIX` loads `_tracker`, `_sampling`, `_signals` and `_output`. The import graph shows `ls.py -> _duct_main.py` as the only edge from a log-reading command into the execution core. `_constants.py` exists for exactly this ("Constants used throughout con-duct").
- **Proposed change**: move both names to `_constants.py` unchanged (the `os.getenv` call included, so the moment it is evaluated stays import time), import them from there in `ls.py` and `cli.py`, and keep `from con_duct._constants import DUCT_OUTPUT_PREFIX, EXECUTION_SUMMARY_FORMAT` in `_duct_main.py` so `test/utils.py:26` and any outside importer keep working. Changing *when* the variable is read is a behavior change and is NV-1.
- **Confidence it's safe**: **High**. `git grep -n 'DUCT_OUTPUT_PREFIX\|EXECUTION_SUMMARY_FORMAT' -- src test` lists every user: `cli.py`, `ls.py`, `_duct_main.py`, `test/utils.py`; none patches the name. Note that `cli.py` still imports `_duct_main`, so this alone does not lift the platform gate of NV-7.
- **Verification**: baseline; `ruff analyze graph --isolated src` must no longer list `_duct_main.py` under `ls.py`.

#### ARC-2 — The `info.json` field names are written out in five places, their formats in two

- **Location**:
  - system fields: `src/con_duct/_models.py:60-79` (`SystemInfo`), `src/con_duct/_tracker.py:101-121` (construction), `src/con_duct/ls.py:44-77` (`NON_TRANSFORMED_FIELDS`), `src/con_duct/ls.py:166-181` (0.2.3 backfill), `test/test_ls.py:118-133` (a verbatim copy of the backfill list; jscpd at 4 lines/30 tokens reports the 16-line clone)
  - formats: `src/con_duct/ls.py:28-42` (`VALUE_TRANSFORMATION_MAP`), `src/con_duct/pprint_json.py:16-29` (`get_field_conversion_mapping`)
- **Issue**: adding one system field means editing four source lists and one test list. The two format maps classify the same twelve fields (`"peak_rss": "{value!S}"` in one, `"peak_rss": "S"` in the other) and have already drifted in intent: `ls` renders `start_time` as `{value:.2f!N}`, `pp -H` as a date (`"D"`); `exit_code` exists only in the `ls` map. `test_schema.py` catches a missing `ls` field, but nothing ties the other copies together.
- **Proposed change**: in steps, each behavior-preserving. (1) Name the backfill list once, `_SYSTEM_FIELDS_ADDED_IN_0_2_3` in `ls.py`, and import it in `test_ls.py`; it must stay a frozen literal, since it records history rather than the current dataclass. (2) Build the system part of `NON_TRANSFORMED_FIELDS` from `dataclasses.fields(SystemInfo)`. (3) Keep the two format maps (they intentionally differ for the time fields) but put them side by side in one module with a comment saying so, or derive the `S`/`P` entries of one from the other.
- **Confidence it's safe**: **Medium**. Step 2 changes the order of `LS_FIELD_CHOICES`: `--help` sorts it (`cli.py:437`), but argparse's "invalid choice" message lists choices in list order. Sort the derived list or accept the message change.
- **Verification**: baseline (`test_schema.py::test_info_fields` is the guard), and `python -c "from con_duct.ls import LS_FIELD_CHOICES as c; print(sorted(c))"` before and after must match.

#### ARC-3 — The package version is computed twice, and a third copy is written but never read

- **Location**: `src/con_duct/_duct_main.py:15`, `src/con_duct/_tracker.py:23` (both `__version__ = version("con-duct")`); `pyproject.toml:71-72` (`[tool.versioningit.write] file = "src/con_duct/_version.py"`), `.gitignore` ("Produced by versioningit")
- **Issue**: two modules each call `importlib.metadata.version`. `con_duct.__version__` comes from the first, the `duct_version` written to `info.json` from the second (`_tracker.py:219`). Meanwhile every build writes `_version.py`, which nothing imports: `git grep -n '_version' -- src test` finds only `__schema_version__` and field names.

Separately decide about `_version.py`: either read the version from it, or drop the `[tool.versioningit.write]` table and the `.gitignore` entry. Dropping it removes a file from the wheel, so that half is a maintainer's call.
- **Confidence it's safe**: **High** for the single definition (no test patches either name: the `mock.patch("con_duct.…")` targets in `test/` are `LogPaths`, `os.*`, `subprocess.*`, `shutil.which`, `lgr`, `TailPipe`, `sys.*`, `ls`, `pprint`, `argparse.ArgumentParser`). **Medium** for removing the written file.
- **Verification**: baseline; `python -c "import con_duct, con_duct._tracker as t; assert con_duct.__version__ == t.__version__"`; for the file removal, `python -m build` before and after and diff the wheels' file lists.

#### ARC-4 — Two functions hold most of the complexity

- **Location**: `src/con_duct/plot.py:307-580` (`matplotlib_plot`), `src/con_duct/_duct_main.py:37-208` (`execute`)
- **Issue**: `lizard` (static) reports `matplotlib_plot` at 274 lines, cyclomatic complexity 34, and `execute` at 172 lines, 21, with 14 parameters. The next largest function in `src/` is `get_system_info` at 66 lines, complexity 6. `matplotlib_plot` does four jobs in sequence: import matplotlib, choose and verify a backend (`plot.py:309-419`, twelve `return 1` exits in total), load and validate two files (`421-455`), and draw (`457-580`). `execute` validates, opens streams, starts three threads, waits, and writes the report.
- **Proposed change**: extract along the existing seams, moving code without editing it: `_ensure_backend(args) -> int | None` (returns an exit code or `None`), `_load_plot_data(args) -> tuple | int`, `_draw(...)`. In `execute`, extract the stream opening (see DUP-2) and the thread start/join pairs. For the 14 positional parameters, a follow-up is a small config dataclass; `execute` is public API (`__all__`), so its signature must keep accepting today's calls.
- **Confidence it's safe**: **Medium**. Tests patch `con_duct._duct_main.subprocess.Popen`, `LogPaths`, `os.makedirs` and `os.path.exists` by module path; helpers that stay in the same module keep those patches effective, helpers moved to another module would not. `test_plot.py` drives `matplotlib_plot` through `args`, so its internals can move freely within `plot.py`.
- **Verification**: baseline, with the py313 coverage for `plot.py` and `_duct_main.py` not dropping; `lizard -l python src` to confirm the numbers moved.

### Duplication

#### DUP-1 — The `ps` line parser exists twice

- **Location**: `src/con_duct/_sampling.py:46-60` (Linux), `src/con_duct/_sampling.py:92-107` (macOS)
- **Issue**: both split a line into the same eight columns and build the same `ProcessStats`:
  ```python
  pid, pcpu, pmem, rss_kib, vsz_kib, etime, stat, cmd = line.split(maxsplit=7)
  ...ProcessStats(pcpu=float(pcpu), pmem=float(pmem), rss=int(rss_kib) * 1024, vsz=int(vsz_kib) * 1024,
                  timestamp=datetime.now().astimezone().isoformat(), etime=etime, stat=Counter([stat]), cmd=cmd)
  ```
  The macOS copy differs only in variable names (`rss_kb`) and in filtering by pid first. Each copy is under the project's 50-token jscpd threshold, which is why the hook passes.
- **Proposed change**: one `_parse_ps_line(line) -> tuple[int, ProcessStats]` used by both; the macOS path keeps its `pid_to_matching_sid` filter before calling `add_pid`.
- **Confidence it's safe**: **Medium**. The Linux path is covered here; the macOS path runs only in the macOS CI jobs. On macOS the helper would build a `ProcessStats` for every process before filtering unless the pid check stays first, so keep the check ahead of the parse.
- **Verification**: baseline locally, plus the `macos-*` jobs of `.github/workflows/test.yaml`.

## Needs verification

#### NV-1 — `DUCT_OUTPUT_PREFIX` set in a `.env` file is ignored

- **Location**: `src/con_duct/_duct_main.py:19`, `src/con_duct/cli.py:10`, `cli.py:270`, `cli.py:528`, `src/con_duct/ls.py:356`
- **Observation**: the variable is read when `_duct_main` is imported, which `cli.py:10` does before `main()` calls `load_duct_env_files()` (`cli.py:528`). Every other `DUCT_*` default is read later, when the parsers are built. OBSERVED with `.duct/.env` containing `DUCT_OUTPUT_PREFIX=fromenv/{pid}_` and `DUCT_MESSAGE=hello-from-env`: `con-duct run true` wrote `.duct/logs/…_info.json` (no `fromenv/`), and that file had `"message": "hello-from-env"`. The help text's own example sets `DUCT_OUTPUT_PREFIX` in a `.env` file (`cli.py:169`), and `test/test_env_files.py` has no test for it. `con-duct ls` without paths globs the same constant.
- **Why it is not a quality change**: reading the variable after the `.env` files load makes a setting that is ignored today take effect, moving where logs are written for anyone who has such a line.
- **To decide**: fix (read it in `_create_run_parser` and in `ls()` like the others, with a regression test) and how to announce it.

#### NV-2 — Exit status 247 instead of 137 for a signal-killed command in one configuration

- **Location**: `src/con_duct/_tracker.py:183-188`, `src/con_duct/_duct_main.py:195-208`
- **Observation**: the conversion of a negative `returncode` to `128 + signal` is a side effect of reading the `execution_summary` property. `execute()` returns `report.process.returncode` and so depends on something having read that property first: `dump_json()` (only with a system summary) or `execution_summary_formatted` (only when logs are kept). OBSERVED:
  ```
  con-duct run sh -c 'kill -9 $$'                                      → 137
  con-duct run -t processes-samples sh -c 'kill -9 $$'                 → 247
  con-duct run -t processes-samples --fail-time 0 sh -c 'kill -9 $$'   → 137
  ```
  In the middle case neither reader runs, `-9` reaches `sys.exit`, and the shell sees 247.
- **Why it is not a quality change**: the fix changes an exit status.
- **To decide**: normalise the return code once, right after `process.wait()` (`_duct_main.py:171`), and make the property free of side effects; add the middle case to `test_e2e.py`.

#### NV-3 — `DUCT_COLORS` enables colors for any non-empty value, and two variables are undocumented

OBSERVED: `DUCT_COLORS=0 con-duct run true` emits 5 lines with escape sequences, 0 without the variable. `args.colors` is then a `str` where `execute` declares `bool`. `DUCT_COLORS` and `DUCT_FAIL_TIME` are read but missing from the "environment variables" list in the help text.
